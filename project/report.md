## 2. Постановка задачи и контекст

1. **Предметная область и задача:**
В данном проекте решается задача регрессии, так как мы предсказываем значение непрерывной величины - цены автомобиля.
Подобный сервис может использоваться на площадках объявлений, чтобы помочь продавцам оценить свой автомобиль. Покупатели также смогут увидеть оценку стоимости и сравнить ее с указанной в объявлении ценой.

2. **Формулировка задачи в терминах ML/ИИ:**
Входные данные являются табличными. пристутствуют числовые и категриальные признаки. Модель должна на выходе предсказывать непрерывную величину. Данные должны вводиться пользователем в виде набора полей.

3. **Целевые метрики качества:**
В качестве метрик качества используем MAE, RMSE, MAPE и R^2,  з которых основной является RMSE. Данные метрики явялются классическими метриками для моделей регрессии.

## 3. Данные

1. **Источник данных:**
Используется открытый датасет `Used Cars`: https://www.kaggle.com/datasets/thedevastator/uncovering-factors-that-affect-used-car-prices

2. **Структура данных:**
Исходный датасет представляет собой размеченные табличные данные, содержащие 371528 строк. Данные содержат цеелвую числовую колонку, 7 числовых и 13 категориальных признаков.

3. **Предобработка и EDA:**
В ходе разведочного анализа данных было выяснено, что:
- Присутствует константная числовая колонка `nrOfPictures`
- В качестве идентификатора записи выступает числовая колонка `index`, она не содержит пропусков и дубликатов
- Доля строк, для которых ни во одном из полей нет пропусков, составляет 70.24%
- Присутствуют аномальные значения в колонках `price`, `yearOfRegistration`, `powerPS`.
- В бинарных категориальных колонках `seller` и `offerType` сильнейший дизбаланс значений

В связи с этими выводами был разаработан алгоритм предобработки данных:
- Полностью удалены столбцы: 
   - index             - ID записи
   - nrOfPictures      - константный
   - seller, offerType - почти константные
   - abtest            - флаг, на цену не влияет
   - dateCreated       - дата создания записи
   - name              - 233к уникальных значений, для обучения бесполезно
   - postalCode        - требует слишком сложный feature-engineering

- Удалены все строки, в которых содержится пропуск хотя бы в одном столбце, так как размер датасета позволяет.
- Убраны все аномальные значения по 99 перцентилю.
- Все категориальные значения кодировались целыми числами по порядку появления значений в исходном датасете. Получившееся отображение записано в [`configs/categorial_map.json`](configs/categorial_map.json).
- Добавлен числовой признак `monthCrawled`, чтобы уловить сезонные колебания цены.

## 4. Модели и подходы

В ходе экспериментов использовались следующие модели:

1. **Базовые (baseline) модели:**
   - `DummyRegressor` (median): RMSE = 6856 
   - `LinearRegression`: RMSE = 3748

2. **Улучшенные модели и эксперименты:**
   - `RandomForestRegressor` с перебором гиперпараметров `n_estimators` и `min_samples_leaf`: RMSE = 2037.6
   - `CatBoost` (iterations=1000, learning_rate=0.03, depth=8, loss_function='RMSE'): RMSE = 2021.9 

Все эксперименты находятся в ноутбуке [`notebooks/model_experiments.ipynb`](notebooks/model_experiments.ipynb)

## 6. Архитектура решения и сервис

1. **Архитектура пайплайна:**
Скрипт data_loader.py отвечает за предобработку данных. Он генерирует обработанный датасет, который используется для обучения модели. Основная модель обучается отдельно в notebooks/model_experiments.py. Скрипт train.py обучает мини-модель на небольшой демонстрационной выборке данных. Сервис работает следующим образом:
1) Получение HTTP-запроса от пользователя
2) Валидация запроса и возврат ошибки, если признаки указаны неверно
3) Трансформация введенных данных в признаки для модели
4) Инференс на основной модели и возврат HTTP-ответа.


2. **API и endpoints:**
   - реализованы эндпоиинты `/health` и `/predict`
   - `/predict` принимает следующие параметры:
      - brand: производитель автомобиля (строка),
      - model: модель автомобиля (строка),
      - dateOfRegistration: дата регистрации автомобиля (строка в формате DD.MM.YYYY),
      - powerPS: мощность двигателя в л.с. (целое число),
      - mileage: пробег в км (целое число),
      - gearbox: тип КПП (строка),
      - fuelType: тип топлива (строка),
      - notRepairedDamage: наличие повреждений (булево),
      - vehicleType: тип кузова (строка),
      - dateCrawled: дата загрузки объявления (строка в формате DD.MM.YYYY)
   - При корректном вводе данных `/predict` возвращает:
      - price: предсказанная цена (дробное число)
      - latency_ms: время обработки запроса (дробное число)
   - При некорректном вводе данных `/predict` вернет ошибку 400 и список параметров, которые были введены неверно.

3. **Технологический стек:**
- Для обучения модели используется `sklearn` и `catboost`.
- Для работы с данными: `numpy`, `pandas`
- Для обертки в сервис: `FastAPI`
Сервис запускается с помощью `Docker`. иструкция по запуску находится в [`README.md`](README.md)
